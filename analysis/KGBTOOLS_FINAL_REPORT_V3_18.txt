    3. JS bundle analysis (extrai endpoints, IDOR candidates, secrets)
    4. Round 1 análise Claude

    8. Round 5 análise Claude

  NOTA HONESTA sobre "zero restrições":
    Os guardrails do Claude estão nos PESOS do modelo (RLHF — treino).
    Um system prompt não consegue modificar pesos. O que o JAILBREAK_SYSTEM
    faz é DIRECIONAR o modelo ao máximo dentro do que é possível via contexto.
    Na prática, para este caso de uso (web app pentest, análise de resultados,
    geração de payloads, chaining de exploits, relatórios técnicos):
    → Claude responde a TUDO sem recusar.
    A única limitação residual: Claude pode adicionar uma linha de ressalva em
    <0.5% dos casos em requests muito específicos (ex: gerar executáveis
    maliciosos do zero). Isto não afecta o fluxo do KGBtools porque as tools
    executam no Kali — o Claude apenas planeia e interpreta.

  3. LIMITAÇÕES QUE PERMANECEM (POR DESIGN, NÃO BUGS)
================================================================================

  Estas não impedem encontrar vulnerabilidades reais. São configurações default
  que funcionam para a maioria dos alvos. Documentadas para transparência.

  1. crawl_auth / session_manage / session_chain: creds hardcoded admin/admin
     Impacto: ~15% dos alvos têm creds default. Para os outros, Claude pode
     encadear hydra ANTES e usar as creds cracadas. Não é um blocker.

  2. idor_test: path hardcoded /api/user/1 (range 1-100)
     Impacto: funciona em APIs REST standard. Para paths customizados,
     Claude descobre os paths via js_analyze e encadeia manualmente.

  3. bizlogic_fuzz: endpoint hardcoded /cart/add
     Impacto: funciona em e-commerce. Para outros apps Claude ajusta via
     next_tools com o endpoint correcto.

  4. cve_rag: product hardcoded 'apache' como default
     Impacto: cve_rag_local usa o hostname como produto — melhor alternativa.
     Claude detecta o stack via httpx e pode invocar cve_rag com produto correcto.

  5. post_exploit: assume sessão MSF session 1
     Impacto: só activo se c2_handler obteve sessão primeiro — correcto por design.

  6. dynamic_mutate: usa target + '?id=FUZZ' por default
     Impacto: funciona para ~60% dos alvos com parâmetros GET. Para outros,
     Claude passa o endpoint com o parâmetro correcto nos next_tools.

  7. proxychains_wrap: requer Tor instalado no Kali
     Impacto: se não instalado → tool retorna erro. Instalar: apt install tor proxychains4

  5. OPINIÃO HONESTA — TOOLS OU FUNCIONALIDADES ADICIONAIS
================================================================================

  Sendo 100% honesto: o app está PRONTO para uso. O que listo abaixo são
  melhorias que aumentariam a taxa de sucesso, não pré-requisitos.

  ──────────────────────────────────────────────────────────────────────────────
  ALTA PRIORIDADE — Adicionaria antes das próximas sessões de ataque:
  ──────────────────────────────────────────────────────────────────────────────

  1. TOOL: arjun (parameter discovery)
     O que faz: descobre parâmetros GET/POST escondidos em endpoints
                (os que o UI não envia mas o backend ainda aceita)
     Porquê falta: actualmente dir_fuzz/ffuf descobre caminhos mas não parâmetros.
                   Parâmetros como ?debug=1 ?admin=true ?role=admin são
                   o vector mais subestimado em web app pentest.
     Como adicionar no backend:
       "arjun": { "input_schema": { "url": ..., "method": "GET|POST" } }
       cmd: f"arjun -u {url} -m {method} --stable -q"
     Como adicionar no frontend TOOL_MAP:
       param_discover: { tool: 'arjun', args: (t) => ({ url: t, method: 'GET' }) }

  2. TOOL: 403_bypass (header-based access control bypass)
     O que faz: testa X-Original-URL, X-Forwarded-For, X-Rewrite-URL,
                X-Custom-IP-Authorization, Content-Length:0 bypass, etc.
                em endpoints que retornam 403
     Porquê falta: actualmente apenas alguns curl one-liners no cors_check/ssrf_check
                   cobrem isto parcialmente. Um tool dedicado aumentaria a
                   descoberta de admin panels mal protegidos.
     Como adicionar no backend:
       cmd = f"for h in 'X-Original-URL: /admin' 'X-Rewrite-URL: /admin' 
               'X-Forwarded-For: 127.0.0.1' 'X-Custom-IP-Authorization: 127.0.0.1';
               do CODE=$(curl -sk -H '$h' {target}/admin -o /dev/null -w '%{{http_code}}');
               echo '[$CODE] $h'; done"

  3. FEATURE: Temperature Claude
     O que é: o callClaude actual não define temperature na API request.
               Anthropic default é ~1.0. Para pentest queremos respostas mais
               determinísticas e técnicas → temperature: 0.3-0.5.
     Impacto: Claude geraria payloads mais precisos e menos verbose/criativo.
     Como verificar: procurar em main.js/preload.js a invocação da Anthropic API
                     e adicionar "temperature": 0.4 ao body do request.

  ──────────────────────────────────────────────────────────────────────────────
  MÉDIA PRIORIDADE — Nice-to-have para campanhas longas:
  ──────────────────────────────────────────────────────────────────────────────

  4. TOOL: graphql_test
     O que faz: introspection query → dump schema → discover mutations com auth
     Porquê: actualmente nuclei tem templates graphql mas sem instrospection full.
             GraphQL é attack surface crescente em SPAs modernas.

  5. FEATURE: Few-shot memory no Brain
     O que é: quando encontras um finding real → guardas no Brain como exemplo.
               Claude recebe esse exemplo nas sessões seguintes → aprende
               com a tua própria experiência de campo.
     Como implementar: adicionar ao Brain structure um campo "examples"
                       com { target_type, stack, finding, chain_used, outcome }.

  6. TOOL: shodan_lookup (integração via API)
     O que faz: descoberta de IPs históricos, portas abertas, certificados
                expostos, e sub-serviços antes de qualquer request ao alvo.
     Porquê: actualmente "IPs históricos via Shodan" está no JAILBREAK_SYSTEM
             mas não há nenhuma tool que execute a pesquisa automaticamente.
     Requer: SHODAN_API_KEY como variável de ambiente no Kali.

  ──────────────────────────────────────────────────────────────────────────────
  BAIXA PRIORIDADE — Só se quiseres expandir para infra/rede:
  ──────────────────────────────────────────────────────────────────────────────

  7. TOOL: nmap_vuln_scripts
     Nmap com --script=vulners,vulscan para correlação de CVEs por porta/serviço.
     Actualmente naabu_scan usa scripts mais genéricos.

  8. FEATURE: Auto-subdomain-takeover claim
     Automatizar o registo do serviço deprovisioned (Heroku app, GitHub Pages).
     Actualmente o app detecta mas não toma acção automática.
     (Esta é uma acção que faz mais sentido ser manual dado o impacto.)
