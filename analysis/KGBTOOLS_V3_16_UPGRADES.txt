  1. O QUE FOI IMPLEMENTADO
================================================================================

────────────────────────────────────────────────────────────────────────────────
  [1] CONTEXT COMPRESSION — Fim da amnésia entre rounds
────────────────────────────────────────────────────────────────────────────────

  Problema anterior:
    Num scan de 5 rounds, o Claude esquecia o que encontrou nos rounds 1 e 2.
    Ex: "admin:hash123 encontrado no round 2" → round 5 não associava a /admin.
    Perdia correlações críticas entre findings de rounds diferentes.

  Solução implementada:
    roundSummaries[] — array local que guarda um resumo compacto de cada round.
    Formato: "Round 2: [CRITICAL] SQLi confirmed | [HIGH] XSS stored | [HIGH] LFI"
    Antes de cada round N, os últimos 3 resumos são injetados no prompt do Claude.
    Claude entra em cada round com memória dos findings anteriores.

  Impacto estimado: +8-12% correlações cross-round preservadas.


────────────────────────────────────────────────────────────────────────────────
  [2] STEALTH DELAY — Pattern de requests não reconhecível por IDS
────────────────────────────────────────────────────────────────────────────────

  Problema anterior:
    Todas as tools lançavam em Promise.all simultâneo — burst imediato.
    IDS modernos (Snort, Suricata, Cloudflare) detetam por volume/pattern,
    não só por payload. Um burst de 10 requests simultâneos = alerta imediato.

  Solução implementada:
    Entre tools:    delay = (idx × 220ms) + random(0–800ms)
    Entre rounds:   delay = random(400ms–1600ms)
    Tools lançam de forma escalonada, com jitter aleatório.
    Pattern de requests deixa de ser um burst reconhecível.

  Impacto estimado: -60% probabilidade de deteção por rate-based IDS.


────────────────────────────────────────────────────────────────────────────────
  [3] USER-AGENT ROTATION — 8 UAs reais por request
────────────────────────────────────────────────────────────────────────────────

  Problema anterior:
    Requests usavam sempre o mesmo User-Agent — facilmente fingerprinted
    e bloqueado por WAFs que detetam scanners automáticos.

  Solução implementada:
    Pool de 8 User-Agents reais passado como user_agent em cada chamada MCP:
    - Chrome 124 / Windows
    - Chrome 123 / macOS
    - Firefox 125 / Linux
    - Firefox 124 / Windows
    - Safari / iPhone iOS 17.4
    - Chrome / Pixel 8 Android 14
    - Googlebot 2.1
    - curl/8.7.1
    Rotação aleatória por cada chamada de tool.

  Impacto estimado: Bypass de WAFs básicos que bloqueiam por UA.


────────────────────────────────────────────────────────────────────────────────
  [4] JS BUNDLE AUTO-ANALYSIS — Engenharia reversa da lógica do alvo
────────────────────────────────────────────────────────────────────────────────

  Problema anterior:
    playwright_crawl encontrava .js bundles mas ninguém os analisava.
    Endpoints de API, hardcoded secrets, fluxos de auth ficavam invisíveis.
    Era o maior gap entre o app e um profissional humano.

  Solução implementada:
    Após playwright_crawl, o sistema extrai URLs de ficheiros .js encontrados
    (até 3 ficheiros) e envia ao Claude para análise de:
      - Endpoints de API não documentados (/api/v1/user, /graphql, etc.)
      - IDOR candidates (IDs, UUIDs em rotas)
      - Hardcoded secrets (tokens, API keys, env vars expostos)
      - Fluxos de autenticação e condições de acesso
      - Rotas internas/admin escondidas no bundle
    Output injetado como "js_bundle_analysis" no contexto dos rounds seguintes.

  Impacto estimado: +15-20% em apps SPA (React/Vue/Angular/Next.js).
  Nota: Este é o upgrade mais impactante para bug bounty moderno.


────────────────────────────────────────────────────────────────────────────────
  [5] CROSS-TOOL CORRELATION — Claude correlaciona resultados entre tools
────────────────────────────────────────────────────────────────────────────────

  Problema anterior:
    buildPrompt apenas dava hints básicos (wordpress → wpscan).
    Sem correlação: se subfinder encontrou admin.target.com e httpx
    confirmava serviço diferente, Claude não tratava como alvo separado.

  Novas regras de correlação adicionadas:
    - SPA detectada (React/Angular/Vue/Next) → playwright_crawl → js_analyze → idor_test
    - API surface (GraphQL/Swagger/OpenAPI) → IDOR em todos os IDs, BOLA, mass assignment
    - Auth surface detectada → brute + credential stuffing + session fixation
    - Info disclosure confirmada → extrai creds ANTES de scanning pesado
    - CVE encontrado → cve_rag → msf_exploit (chain automático)
    - WAF detectado → waf_bypass + evasion_scan ANTES de sqli_scan/ffuf
    - Subdomínio com serviço diferente → trata como alvo separado

  Impacto estimado: +5-8% em decisões corretas de chaining.


================================================================================
  2. COMO USAR O APP HOJE — GUIA RÁPIDO
================================================================================

  PRÉ-REQUISITOS (Kali Linux)
  ─────────────────────────────────────────────────────────────────────────────
  pip3 install playwright mitmproxy
  playwright install chromium
  python3 kali-mcp-server.py      ← deixar a correr

  CONFIGURAÇÃO MÍNIMA (Settings do app)
  ─────────────────────────────────────────────────────────────────────────────
  Anthropic API Key    → obrigatória (console.anthropic.com)
  Kali MCP Server      → http://IP_KALI:3000
  Groq API Key         → opcional (modelos rápidos gratuitos)
  Webhook              → opcional (Telegram/Discord para notificações críticas)

  MODO DE USO RECOMENDADO
  ─────────────────────────────────────────────────────────────────────────────
  1. Define o target (URL completo: https://target.com)
  2. Liga AUTO mode
  3. Clica INICIAR
  4. Lê os logs enquanto corre — não é 100% autónomo, precisas supervisão
  5. No final, relatório HTML é exportado automaticamente

  MODELO A USAR
  ─────────────────────────────────────────────────────────────────────────────
  Claude Opus   → melhor para targets hardened, bug bounty, lógica complexa
  Claude Sonnet → bom equilíbrio velocidade/inteligência para targets normais
  Gemma (Groq)  → rápido e gratuito para recon inicial


================================================================================
  3. RETORNO REALISTA POR TIPO DE TARGET
================================================================================

  TARGET                                   PROB. WIN     TEMPO ESTIMADO
  ──────────────────────────────────────────────────────────────────────
  Info disclosure (/.env, /.git exposto)   ~85-90%       2-5 minutos
  WordPress desatualizado (sem WAF)        ~75-85%       10-20 minutos
  Site PHP sem WAF                         ~65-75%       15-30 minutos
  App com WAF (Cloudflare básico)          ~40-55%       30-60 minutos
  SPA React/Vue autenticada                ~35-50%       45-90 minutos
  Bug bounty target hardened               ~15-30%       2-4 horas
  App zero vulnerabilidades conhecidas     ~5-15%        N/A

  NOTA: "Win" = encontrar pelo menos 1 finding exploitável.
  Comprometimento total (shell) é ~30-40% menos provável que encontrar vuln.

  ONDE O APP É MAIS FORTE:
  - Misconfigs e info disclosure → quase sempre win
  - WordPress / Joomla / CMSs populares → base de CVEs grande
  - Apps sem WAF com SQLi/LFI óbvio → cadeia automática funciona bem
  - Recon e surface mapping em qualquer alvo → sempre útil

  ONDE AINDA PRECISAS DE TI:
  - Lógica de negócio única (preços, transferências, fluxos custom)
  - WAFs avançados com ML (Cloudflare Enterprise, Akamai Kona)
  - Zero-days e vulnerabilidades de design originais
  - Engenharia social e phishing
  - Persistência de longa duração
