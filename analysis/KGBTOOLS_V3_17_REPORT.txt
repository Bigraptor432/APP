  1. BUGS CRÍTICOS CORRIGIDOS NESTA VERSÃO
================================================================================

BUG #1 — Timeout de 60s para todas as tools (CRÍTICO)
───────────────────────────────────────────────────────
  PROBLEMA: Nuclei, sqlmap --crawl, playwright_crawl, wpscan aggressive
            precisam de 3-10 minutos. Com 60s davam timeout → Claude recebia
            output vazio → perdia 40% dos findings reais.

  CORREÇÃO: Timeouts por tool agora específicos:
            - nuclei_fast      → 300s
            - nuclei_exploit   → 240s
            - sqli_scan        → 240s (sqlmap --crawl=2)
            - playwright_crawl → 300s
            - naabu_scan       → 180s
            - msf_exploit      → 120s
            O backend já lia o campo "timeout" dos args — só faltava enviar.

BUG #2 — Output truncado a 2000 chars para todas as tools (CRÍTICO)
────────────────────────────────────────────────────────────────────
  PROBLEMA: Nuclei com muitos findings, info_disclosure com 40+ paths,
            playwright_crawl com URLs descobertas — os dados depois dos
            2000 chars eram descartados antes de chegar ao Claude.

  CORREÇÃO: Tools de output longo recebem agora 5000 chars:
            nuclei_fast, nuclei_exploit, info_disclosure, playwright_crawl,
            js_analyze, sqli_scan, wpscan, cve_rag, cve_rag_local,
            lateral_move, post_exploit.
            Todas as outras tools: 2500 chars (era 2000).

BUG #3 — msf_exploit chamado com cve:'recent' (CRÍTICO)
────────────────────────────────────────────────────────
  PROBLEMA: Quando o AUTO mode detetava CVEs no output do nuclei e adicionava
            msf_exploit ao next_tools, os args do TOOL_MAP usavam cve:'recent'
            como fallback. MSF fazia "search cve:recent" → encontrava nada →
            exploit nunca corria.

  CORREÇÃO: CVE auto-match agora corre msf_exploit INLINE com os CVE IDs
            reais extraídos do output nuclei (até 3 CVEs prioritizados por
            score). Exemplo: nuclei encontra CVE-2021-44228 → msf_exploit
            corre imediatamente com target + cve:CVE-2021-44228.

  2. NOVAS FEATURES ADICIONADAS EM v3.17
================================================================================

FEATURE #1 — post_exploit (C2 Loop Completo)
──────────────────────────────────────────────
  Tool: post_exploit
  Trigger: Automático quando shell_upload ou c2_handler reportam sessão aberta
  O que faz (sequência completa via msfconsole):
    1. Abre MSF handler (multi/handler)
    2. local_exploit_suggester  → privesc vectors
    3. hashdump                 → dump de hashes NTLM/shadow
    4. env dump                 → variáveis de ambiente (tokens, keys)
    5. sshkey_persistence       → instala SSH key para persistência
    6. shell_to_meterpreter     → upgrade de shell para meterpreter
    7. getuid / sysinfo / getpid → fingerprint pós-exploração
    8. checkvm                  → detecta se está em VM/container

FEATURE #2 — dynamic_mutate (Payloads Gerados por Claude)
──────────────────────────────────────────────────────────
  Tool: dynamic_mutate
  Trigger: Automático no round 1 quando WAF bloqueia
  O que faz:
    1. Detecta WAF fingerprint (Cloudflare, Akamai, Imperva, ModSecurity, etc.)
    2. Envia fingerprint + respostas bloqueadas ao Claude
    3. Claude gera 15 payloads SQLi + 10 payloads XSS específicos para esse WAF
       Técnicas: unicode mixing, HPP, chunked encoding, comment obfuscation,
                 null byte, overlong UTF-8, case mixing não-standard
    4. dynamic_mutate testa todos os payloads contra o target
    5. Reporta quais passaram o WAF (marcados como BYPASS!)

FEATURE #3 — proxychains_wrap (IP Rotation via Tor)
─────────────────────────────────────────────────────
  Tool: proxychains_wrap
  Uso: Manual ou via Claude em targets que bloqueiam por IP/geo
  O que faz:
    1. Inicia serviço Tor (service tor start ou tor --RunAsDaemon)
    2. Aguarda 3s para circuit setup
    3. Corre qualquer comando envolvido em proxychains4
    4. Verifica IP após Tor (curl ifconfig.me via proxychains)
  Requisito na Kali: apt install tor proxychains4

FEATURE #4 — cve_rag_local (CVE Lookup Offline)
─────────────────────────────────────────────────
  Tool: cve_rag_local
  O que faz (3 fontes paralelas sem depender do NVD API):
    1. searchsploit <produto> <versão>    → Exploit-DB local
    2. msfconsole search type:exploit     → módulos MSF disponíveis
    3. nuclei -tags cves -search          → templates nuclei com CVE
  Vantagem: Funciona offline, sem rate limiting, mais rápido que NVD API

================================================================================
  5. LIMITAÇÕES CONHECIDAS (POR DESIGN, NÃO BUGS)
================================================================================

  1. admin:admin hardcoded em crawl_auth e session_chain
     → Só funciona em targets com creds default (5-15% dos alvos)
     → Para o resto: Claude terá de encadear brute-force primeiro

  2. post_exploit assume sessão MSF na session 1
     → Funciona correctamente quando c2_handler está ativo antes

  3. proxychains_wrap requer Tor na Kali
     → Instalar: apt install tor proxychains4

  4. playwright_crawl instala venv Python na primeira execução (~2 min)
     → Após instalação é rápido

  5. cve_rag usa NVD API que pode ter rate limiting (5 req/30s sem API key)
     → cve_rag_local é alternativa offline sem limite

  6. msf_exploit com CVE real: só funciona se MSF tiver módulo para esse CVE
     → Para CVEs recentes sem módulo MSF → Claude pode sugerir exploit manual
