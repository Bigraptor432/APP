  1. O QUE FOI IMPLEMENTADO NESTA VERSÃO (v3.19)
================================================================================

  TOOL NOVA 1: param_discover (arjun — hidden parameter discovery)
  ─────────────────────────────────────────────────────────────────
  Backend: kali-mcp-server.py — _NEW_TOOLS + build_command completo
  Frontend: TOOL_MAP, SECONDARY list, AUTO_TOOLS, TOOL_BINS, UI toggle (ON por default)

  O que faz:
    Descobre parâmetros GET/POST que o UI NUNCA envia mas o backend ainda aceita.
    Estes são os parâmetros que nenhum scanner encontra porque não estão nos formulários.
    Exemplos do que encontra: ?admin=true, ?debug=1, ?role=admin, ?bypass=1,
                               ?price=0, ?discount=100, ?internal=true

  Como funciona:
    MODO ARJUN (se instalado):
      arjun -u TARGET -m GET --stable -q
      → usa wordlist de 25k parâmetros comuns, confirma cada um com requests reais
    MODO FALLBACK (se arjun não instalado):
      Testa manualmente 50 parâmetros críticos via curl:
      id, user_id, admin, debug, role, isAdmin, token, api_key, auth, bypass,
      internal, dev, callback, redirect, secret, path, file, action, etc.

  Instalar no Kali: pip3 install arjun

  ──────────────────────────────────────────────────────────────────────────────

  TOOL NOVA 2: 403_bypass (header + path + verb bypass)
  ──────────────────────────────────────────────────────
  Backend: kali-mcp-server.py — _NEW_TOOLS + build_command completo
  Frontend: TOOL_MAP, SECONDARY list, AUTO_TOOLS, TOOL_BINS, UI toggle

  O que faz:
    Quando um endpoint retorna 403/401, testa 4 categorias de bypass:

    1. HEADER INJECTION (12 headers):
       X-Original-URL: /admin
       X-Rewrite-URL: /admin
       X-Forwarded-For: 127.0.0.1
       X-Remote-IP: 127.0.0.1
       X-Remote-Addr: 127.0.0.1
       X-Client-IP: 127.0.0.1
       X-Real-IP: 127.0.0.1
       X-Custom-IP-Authorization: 127.0.0.1
       X-Host: localhost
       X-Forwarded-Host: localhost
       X-Originating-IP: 127.0.0.1
       X-ProxyUser-Ip: 127.0.0.1

    2. PATH NORMALIZATION (11 variantes):
       /admin/.  //admin  ./admin  /admin%20  /admin%09
       /admin?   /admin#  /admin..;/  /admin;.js  /admin/.;/

    3. HTTP VERB TAMPERING:
       POST PUT PATCH DELETE OPTIONS TRACE HEAD

    4. Content-Length: 0 POST trick (bypasses some reverse proxy configs)
    5. nuclei -tags 403,bypass,misconfiguration

    Reporta APENAS os que resultam em código diferente do baseline 403.

  MUDANÇA 3: temperature: 0.4 no Claude API (main.js)

  Impacto:

  DIMENSÃO 1 — FASE 2 PRIMEIRO:
    Antes de qualquer scanner pesado, Claude força a execução de info_disclosure.
    Verifica 15+ paths de baixo ruído: .env, .git, composer.json, source maps,
    /rest/settings, /api/status, /adminer.php, /var/logs/prod.log.
    HTTP 200 em qualquer = CRITICAL imediato antes de alertar qualquer IDS.

  DIMENSÃO 2 — CVE COM EPSS, NÃO SÓ CVSS:
    Claude sabe que CVSS 9.0 sozinho não significa exploitável.
    EPSS > 80% = exploit em uso activo na wild → ataque imediato.
    CISA KEV = já explorado em ataques reais → tentativa obrigatória.
    "Vulnerable but blocked by config" ≠ "Exploitable" — distinção correcta.

  DIMENSÃO 3 — CLOUDFLARE NÃO É OBSTÁCULO:
    Claude pensa SEMPRE no IP de origem antes de atacar.
    Sabe que portainer.*, mail.*, api.*, staging.* frequentemente não são proxied.
    Se encontra IP real → scan directo → todos os WAF/CDN rules ignorados.
    Shodan/SecurityTrails para IPs históricos.

  DIMENSÃO 4 — STACK = ATAQUE IMEDIATO:
    Detecta stack → executa lista específica sem esperar nuclei:
    n8n?        → /rest/settings SEMPRE aberto = Critical imediato
    Portainer?  → POST /api/users/admin/init mesmo em instâncias a correr
    Supabase?   → anon key no JS → schema dump + RLS bypass
    WordPress?  → xmlrpc multicall + /wp-json/wp/v2/users
    Apache<2.4.62? → CVE-2024-38475 path traversal imediatamente

  DIMENSÃO 5 — PARÂMETROS ESCONDIDOS (NOVO em v3.19):
    param_discover corre no AUTO_TOOLS.
    Claude sabe que ?admin=true é um dos vectors mais subestimados.
    UI nunca envia → backend ainda aceita → encontrado apenas por Claude+arjun.
    Encadeado com bizlogic_fuzz quando parâmetros de preço/quantidade encontrados.

  DIMENSÃO 6 — 403 NÃO É FIM (NOVO em v3.19):
    403_bypass corre no AUTO_TOOLS.
    Claude sabe que admin panels com 403 podem ser acessados via headers internos.
    X-Original-URL, X-Forwarded-For, path normalization, verb tampering —
    12 headers + 11 path variants + 7 verbos = 30 vectores por endpoint 403.

  DIMENSÃO 7 — BUSINESS IMPACT PRIMEIRO:
    Não "IDOR encontrado". Sim: "Atacante acede todos os pedidos sem autenticação".
    Duplicate submissions = crítico em qualquer sistema de pagamento/votos.
    Privilege drift (downgrade não revoga sessão) = escalada via sessão antiga.

  DIMENSÃO 8 — CHAINING OBRIGATÓRIO:
    Claude não apenas reporta — sequencia:
    .env encontrado → extrai DB_PASSWORD → testa /admin /phpmyadmin → forja cookies
    403 em /admin → 403_bypass → se bypass OK → admin_takeover → session_chain
    Parâmetros ocultos → ?admin=true → se 200 com conteúdo diferente → Critical
    CVE (EPSS>50%) → msf_exploit → c2_handler → post_exploit → lateral_move


================================================================================
  4. AUDITORIA DE TODOS OS BUGS — HISTÓRICO COMPLETO
================================================================================

  BUG #1 — TIMEOUT FIXO 60s (v3.17a)
    Problema: nuclei a correr 300+ templates com timeout de 60s = sempre cortado
    Impacto: nuclei, sqlmap, playwright nunca terminavam correctamente
    Fix: timeout por tool — nuclei 300s, sqlmap 240s, playwright 300s, msf 120s
    Status: RESOLVIDO ✓

  BUG #2 — OUTPUT TRUNCADO A 2000 CHARS (v3.17a)
    Problema: nuclei retornava 150+ findings mas Claude só via os primeiros 2000 chars
    Impacto: 80% dos findings de nuclei eram cortados antes de chegar ao Claude
    Fix: LONG_OUTPUT_TOOLS = 5000 chars; outros tools = 2500 chars
    Status: RESOLVIDO ✓

  BUG #3 — msf_exploit COM cve:'recent' (v3.17a)
    Problema: msf_exploit recebia sempre cve:'recent' em vez do CVE real encontrado
    Impacto: metasploit não conseguia encontrar módulo para 'recent'
    Fix: extracção do CVE real do output do nuclei via regex /CVE-\d{4}-\d+/gi
         msf_exploit inline com o CVE ID correcto
    Status: RESOLVIDO ✓

  BUG #4 — QUEUE MODE USAVA SEMPRE O MESMO TARGET (v3.17b)
    Problema: runPentest() lia target do DOM state em vez do overrideTarget
    Impacto: fila de 5 alvos → todos atacados com o target do input field
    Fix: const target = overrideTarget !== undefined ? overrideTarget : DOM_input
         id="kgb-target-input" adicionado ao input DOM
    Status: RESOLVIDO ✓

  BUGS ACTUAIS: 0
